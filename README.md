## Создание необходимых инструментов

Для работы с сетью необходимо создать два класса:

- Интерфейс для работы с сетью - NetworkAPI - здесь будут описаны методы, через которые можно обратиться к серверу
- Data class ServerDTO - дата класс с данными, которые получены по сети

Так как эти сущности предоставляют доступ к источнику данных, созданы они должны быть в data слое, а именно в пакете data.cloud

Для примера, мы будем обращаться к серверу на flask:

```python

from flask import Flask, request, jsonify

app = Flask(__name__)

items = [
    {"id": 1, "name": "Первый объект"},
    {"id": 2, "name": "Второй объект"},
    {"id": 3, "name": "Третий объект"}
]

@app.route('/items', methods=['GET'])
def get_items():
    return jsonify(items)

@app.route('/items/<int:id>', methods=['GET'])
def get_item(id:int):
    if id >= len(items):
        jsonify({"error": "Wrong id"}), 400
    return jsonify(items[id])

@app.route('/items', methods=['POST'])
def add_item():
    if not request.is_json:
        return jsonify({"error": "Запрос должен содержать JSON"}), 400

    new_item = request.get_json()

    if not new_item:
        return jsonify({"error": "JSON не должен быть пустым"}), 400

    new_item['id'] = len(items) + 1

    items.append(new_item)
    return jsonify(new_item), 201

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0')
```

На сервере определена структура данных - Item(id, object_name).
Иногда необходимо использовать разные наименования на сервере, в сети и в клиентском приложении, хотя 
такой подход не рекомендуется (но иногда бывает ситуация, что в разных языках используются разные 
системы наименования - camelCase и snake_case например, тогда без этого не обойтись)

Для этого можно перед полем добавить аннотацию @SerializedName - тогда в Json будет использоваться 
название из аннотации, а в коде клиентского приложения - название поля. В случае, если эти названия 
совпадают, необязательно использовать такую аннотацию

![img_4.png](img_4.png)

Для этого сервера нам нужно 3 метода: 
- метод получения списка записей; 
- метод получения одной записи; 
- метод создания новой записи.

Поэтому в NetworkAPI мы и создаём 3 метода, аннотированных соответствующими аннотациями.

![img_5.png](img_5.png)

Есть несколько способов получить данные из NetworkAPI. Из-за того, что вызов сервера должен происходить 
не на главном потоке (иначе приложение залагает до момента получения данных, это недопустимо), данные 
получаются либо в виде Callback'a - специальной функции, которая вызывается в момент, когда она нужна, 
либо сама функция должна быть прерывающейся - suspend функцией.

## Использование серверных вызовов

Чтобы вызвать сервер и получить / передать данные на сервер, необходимо создать объект написанного интерфейса. 
Для этого нужно создать объект retrofit'a и через него создать объект интерфейса. 
Эти объекты должны быть глобальные, поэтому мы можем создать объект, в котором будут все необходимые 
параметры. Объект создаётся один на всю запущенную программу.
